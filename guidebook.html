📘 The Complete Beginner's Guide to Git & GitHub

Everything you need to master local version control and team collaboration, explained clearly with real-world examples.

1. Git vs. GitHub: The Fundamental Difference

A common beginner confusion is treating Git and GitHub as identical. They solve two different halves of the puzzle:

Feature Git GitHub
What it is Command-line tool installed on your computer. Cloud hosting platform and developer website.
Internet needed? No. Completely functional offline. Yes. Required for syncing and browsing.
Core duty Track file revisions, branch, merge, commit. Team pull requests, backup, issues, code reviews.
Simple Analogy: Git is your word processor saving file history locally; GitHub is Google Drive where you upload documents to collaborate with teammates.

2. The Core Mental Model: 4 Zones

Every Git action moves code through 4 distinct stages:

  1. Working Directory: The regular files on your hard drive you edit with VS Code or any text editor.
  2. Staging Area (Index): The staging line where you pick which changes will go into the next commit (git add).
  3. Local Repository (.git): The permanent history database safely stored on your machine (git commit).
  4. Remote Repository: The cloud copy on GitHub (git push / git pull).

3. First-Time Configuration

Configure your name and GitHub email once:

git config --global user.name "Your Name"
git config --global user.email "your-github-email@example.com"
git config --global init.defaultBranch main

4. The Daily Commit Cycle (Status, Add, Commit)

The standard rhythm of day-to-day coding:

# Check what has changed
git status

# Stage specific file or all files
git add src/index.html
git add .

# Save snapshot with conventional message
git commit -m "feat: implement profile user card"

# Review recent snapshots
git log --oneline -n 5

5. Branching and Merging

Branches let you experiment freely without breaking the stable main branch:

# Create and jump into new branch
git switch -c feature/dark-mode

# (Code, edit files, test)
git add .
git commit -m "feat: complete dark mode styles"

# Switch back to main branch
git switch main

# Merge the completed feature
git merge feature/dark-mode

# Clean up branch after merge
git branch -d feature/dark-mode

6. Working with GitHub (Remote, Push, Pull)

# Connect local repo to GitHub
git remote add origin https://github.com/USER/REPO.git

# First push to GitHub
git push -u origin main

# Subsequent pushes
git push

# Download latest changes from teammates
git pull origin main

7. Undoing Mistakes & Git Revert

How to undo changes safely:

The Safest Way to Undo: git revert
Instead of rewriting or deleting history (which breaks shared team repositories), git revert creates a brand-new commit that undoes the exact changes made in the bad commit. 
# 1. Locate the bad commit hash
git log --oneline -n 5
# Example output: a3f89b2 feat: buggy script

# 2. Revert that commit
git revert a3f89b2 --no-edit

# 3. Push the fix to GitHub
git push

8. Resolving Merge Conflicts

When Git encounters two conflicting changes on the same line, it inserts markers:

<<<<<<< HEAD
<h1>Welcome to My Shop</h1>
=======
<h1>Welcome to Farhad's Store</h1>
>>>>>>> feature/title-update

Simply delete the lines you don't want, remove the marker lines, stage the file with git add, and commit!
