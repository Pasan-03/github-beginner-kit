📦 What is Git?

  • Local version control software on your machine
  • Runs 100% offline — no Wi-Fi needed
  • Takes precise snapshots of your project over time

☁️ What is GitHub?

  • Cloud platform to store your Git repositories
  • Enables collaboration, Pull Requests & Code Reviews
  • Acts as your developer portfolio and backup

📦 How to Push: Step-by-Step Flow

Watch the file move through the 4 zones on each click:

1. Edit File
2. git add .
3. git commit
4. git push
1. Working Tree
📄 index.html [+3 -1]
➔
2. Staging Area
✅ index.html (ready)
➔
3. Local Repo
🔖 [c8f2a1]
feat: login
➔
4. GitHub Cloud
☁️ Awaiting Push...
bash — status check
user@mac:~$ git status
On branch main Changes not staged for commit:   modified:  src/index.html
Move 1: You modified src/index.html in your editor. It's in your Working Directory (red/unstaged). Git sees the change, but it isn't ready for commit yet.
bash — stage changes
user@mac:~$ git add src/index.html
user@mac:~$ git status
Changes to be committed:   modified:  src/index.html
Move 2: Running git add . (or git add src/index.html) stages the file! It turns green and is now drafted for the snapshot.
bash — record snapshot
user@mac:~$ git commit -m "feat: add user login form"
[main c8f2a1] feat: add user login form  1 file changed, 3 insertions(+), 1 deletion(-)
Move 3: Running git commit packages the staged files into a permanent snapshot stored in your Local Repository with hash c8f2a1.
bash — sync with GitHub
user@mac:~$ git push origin main
Writing objects: 100% (3/3), 320 bytes, done. To https://github.com/farhadlafarie/github-beginner-kit.git   main -> main
Move 4: Running git push origin main uploads your local commit to GitHub Cloud! Your code is now safely backed up and visible to your team.

Animated Feature Flow #2

🌿 Branching: Work in Parallel Universes

Never break production! Watch how a branch diverts work safely:

1. On Main
2. Create Branch
3. Commit on Branch
4. Switch Back to Main
C1
base
C2
stable
C3
main branch
F1
feature/dark-mode
bash — check branch
user@mac:~$ git branch
* main
Move 1: You are standing on the main branch at commit C3. Any changes directly made here risk breaking your production site.
bash — branch creation
user@mac:~$ git switch -c feature/dark-mode
Switched to a new branch 'feature/dark-mode'
Move 2: git switch -c feature/dark-mode spawns a new branch pointer right where you are. You have entered a safe sandbox!
bash — commit on branch
user@mac:~$ git add style.css && git commit -m "feat: add dark theme colors"
[feature/dark-mode 7e4a19] feat: add dark theme colors
Move 3: You make commit F1. Notice that F1 exists ONLY on the feature/dark-mode branch! main is completely untouched.
bash — return to main
user@mac:~$ git switch main
Switched to branch 'main'
Move 4: You switch back to main. In your editor, the dark mode code temporarily disappears! It is safely stored inside feature/dark-mode awaiting a merge.

Animated Integration Flow #3

🔀 Merging: Combining Feature into Main

Once your feature is tested and reviewed, bring it back into production:

1. Switch to Target (main)
2. git merge
3. Clean Up Branch
C3
main
F1
feature/dark-mode
M1
Merged into main
bash — verify active branch
user@mac:~$ git switch main
Already on 'main'
Rule of Merging: Always stand on the branch you want to receive the changes (in this case, main)!
bash — merge
user@mac:~$ git merge feature/dark-mode
Updating c8f2a1..7e4a19 Fast-forward  style.css | 18 ++++++++++++++++++
Merge Executed: Git brings commit F1 into main. Now main contains the dark mode styles!
bash — branch deletion
user@mac:~$ git branch -d feature/dark-mode
Deleted branch feature/dark-mode (was 7e4a19).
Housekeeping: Once merged, delete the feature branch so your repository stays tidy and uncluttered.

Animated Collaboration Flow #4

⬇️ Pulling: Syncing Team Commits from GitHub

What happens when someone pushes to GitHub and you need their updates?

1. Teammate Pushes to GitHub
2. git fetch (Download)
3. git merge (Integrate)
GitHub Cloud
🔖 [d4e9b1]
teammate: add footer
⬇️
Local Repo (.git)
📥 [d4e9b1] Downloaded!
➔
Working Files
✨ footer.html (Updated)
Move 1: Your teammate committed and pushed commit [d4e9b1] to GitHub. Your computer doesn't know about it yet!
bash — fetch
user@mac:~$ git fetch origin
From https://github.com/farhadlafarie/github-beginner-kit   main -> origin/main (new commits detected)
Move 2 (Fetch): git fetch downloads the commits into your local cache without touching your editor files yet.
bash — pull
user@mac:~$ git pull origin main
Updating 7e4a19..d4e9b1 Fast-forward  footer.html | 24 ++++++++++++++++++++++++
Move 3 (Merge): git pull automatically performs both fetch and merge in a single command, updating your working files instantly!

Animated Undo Flow #5

⏪ Git Revert: The Safe Emergency Brake

A bug got committed? Here is how to safely undo it without destroying history:

1. Bug Discovered
2. Identify Commit Hash
3. git revert <hash>
4. Push Revert to GitHub
C1
Stable Base
C2
Buggy Commit
R1
Revert of C2
🚨 Uh oh! Commit C2 broke the login button in production. You need to roll it back right away!
bash — inspect log
user@mac:~$ git log --oneline -n 2
b91c28f feat: experimental login button (BROKEN) e7a2091 feat: stable navigation
Move 2: We inspect the log and find the commit hash: b91c28f.
bash — revert
user@mac:~$ git revert b91c28f --no-edit
[main 4f8812a] Revert "feat: experimental login button"  1 file changed, 5 deletions(-)
Move 3 (The Magic of `git revert`): It does NOT erase b91c28f! Instead, it creates a new forward commit 4f8812a that exactly cancels out the bug!
bash — push revert
user@mac:~$ git push origin main
To https://github.com/farhadlafarie/github-beginner-kit.git   main -> main
Move 4 (Zero Conflicts): Because it is a normal forward commit, you can safely push to GitHub with no force-pushing and zero issues for teammates!

Bonus Pro Trick #6

💼 Git Stash: The Secret Pocket

What if your boss asks for an urgent bug fix, but you have half-finished uncommitted work?

1. Half-Finished Work
2. git stash (Pocket It!)
3. git stash pop (Restore It!)
bash — dirty working tree
user@mac:~$ git status
modified:  src/complex-feature.js (half-written, broken syntax)
Move 1: You cannot commit because the code is broken and unfinished. But you need a clean working directory right now!
bash — stash away
user@mac:~$ git stash
Saved working directory and index state WIP on main: c8f2a1 user@mac:~$ git status
nothing to commit, working tree clean
Move 2 (Magic Stash): Git sweeps all dirty edits into an internal shelf. Your workspace is instantly 100% clean so you can fix the urgent bug!
bash — pop stash
user@mac:~$ git stash pop
Auto-merging src/complex-feature.js Dropped refs/stash@{0}
Move 3 (Back to Work): git stash pop empties the pocket and restores your half-written work right where you left off.
