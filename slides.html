🚀 Mastering Git & GitHub

The definitive visual guide to Commits, Branches, Push, Pull, and Safe Reverts

📦 What is Git?

  • A local version-control engine installed on your PC
  • Takes historical snapshots of files
  • Works completely offline — no internet needed
  • Gives you branching and safe undo capabilities

☁️ What is GitHub?

  • A cloud platform for hosting your Git repositories
  • Collaboration platform for engineering teams
  • Pull requests, code reviews, issues, and CI/CD
  • Your public developer portfolio and resume

💡 Quick Analogy: Git is like taking photos with a camera; GitHub is posting the album online for your friends.

Mental Model

🧠 The 4 Zones of Git

Before typing commands, understand where your code travels:

1. Working Dir
Your actual files in VS Code / Editor
➔
2. Staging Area
git add
Drafting the next snapshot
➔
3. Local Repo
git commit
Permanent snapshot on disk
➔
4. Remote (GitHub)
git push
Cloud repository backup

Why do we need a Staging Area?

It lets you craft precise, clean commits. If you changed 5 files, you can choose to commit only 2 of them right now, and the other 3 in a separate commit!

Step 1: Setup

⚙️ First-Time Configuration

Run these once on any new computer so your commits have your identity:

Terminal (macOS / Linux / Windows) 
# 1. Set your name
git config --global user.name "Farhad"

# 2. Set your GitHub email address
git config --global user.email "farhadlafarie@gmail.com"

# 3. Set standard default branch name
git config --global init.defaultBranch main

# 4. Check that it was saved
git config --list

⚠️ Important Tip

Use the exact same email associated with your GitHub account so GitHub links your commits to your profile picture and contribution graph!

The Daily Cycle

📸 The Commit Lifecycle

This is the cycle you will repeat every single day as a software engineer:

Daily Workflow Commands 
# 1. Check what has changed in your project
git status

# 2. Stage a specific file (or '.' for all files)
git add index.html
git add style.css

# 3. Commit your snapshot with a clear description
git commit -m "feat: create responsive landing page"

# 4. View your history
git log --oneline

✅ Good Commit Message

feat: add user login form validation
Explains what was added and why.

❌ Bad Commit Message

update code or fixed stuff
Gives zero context to your future self or teammates.

Branching

🌿 Branching: Code in Parallel

A branch is an independent timeline. Work on new ideas without endangering the stable main code.

Branching Commands 
# 1. View all local branches
git branch

# 2. Create and jump into a new branch
git switch -c feature/dark-mode

# 3. Work on code, then add and commit
git add style.css
git commit -m "feat: add dark mode theme variables"

# 4. Switch safely back to main branch
git switch main

💡 Rule of Thumb

Always keep main clean and working. Never develop directly on main when working with a team — always create a feature branch!

Merging

🔀 Merging: Combining Branches

Once your feature branch is tested and ready, merge it back into main.

main branch
Stable base
➔
feature branch
Build & Commit feature
➔
git merge
Fold changes into main
Merge Commands 
# Step A: Switch to the receiving branch
git switch main

# Step B: Merge the completed feature
git merge feature/dark-mode

# Step C: Delete branch after merge (keeps repo clean)
git branch -d feature/dark-mode
Cloud Sync

☁️ GitHub: Remote, Push & Pull

Connect your computer to GitHub to back up code and collaborate.

⬆️ git push

Uploads your local commits up to GitHub cloud.

git remote add origin <URL>
git push -u origin main

⬇️ git pull

Downloads new team commits from GitHub to your laptop.

git pull origin main

🔄 The Daily Team Rhythm

Start of day: git pull (get everyone's updates) ➔ End of day: git push (share your commits).

Undo Safely

⏪ Git Revert: Safe Time Travel

What if a committed bug slipped in? git revert is the safest undo mechanism!

Reverting a Bad Commit 
# 1. View your commit history
git log --oneline -n 3
# Output: 9a8b7c6 feat: accidentally broken feature

# 2. Revert that specific commit
git revert 9a8b7c6 --no-edit

# 3. Push the fix safely to GitHub
git push

🛡️ Why `git revert` is Safe

It doesn't delete history. It generates a new commit that cancels out the bad code. Teammates won't get merge errors!

⚠️ Why `git reset --hard` is Dangerous

It destroys history. If you already pushed to GitHub, you will break your teammates' copies! Avoid reset on public branches.

Cheatsheet

📋 The Essential Cheat Sheet

Local Commands

  • git init : Start new repository
  • git status : Check working tree
  • git add . : Stage all changes
  • git commit -m "msg" : Record snapshot
  • git log --oneline : View summary history
  • git restore <file> : Discard uncommitted edits

Branch & Remote Commands

  • git switch -c <name> : Create & switch branch
  • git switch <name> : Jump to branch
  • git merge <name> : Merge into current
  • git push origin <branch> : Send to GitHub
  • git pull : Receive from GitHub
  • git revert <hash> : Undo commit safely
